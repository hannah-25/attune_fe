# 데이터 규칙 (오프라인 캐시 / 큐 / 게스트 목)

## 데이터 출처 3종

| 출처 | 위치 | 언제 |
|------|------|------|
| 실제 백엔드 | `fetch` via `client.ts` | 온라인 + 로그인 |
| 오프라인 캐시/큐 | `offline/` (Dexie) | 오프라인 / 서버 5xx(GET) / 직전 네트워크 실패 |
| 게스트 목 | `mocks/` | `isGuestMode()` true (auth/account 제외) |

## 캐시 규칙

- 🟢 성공한 **GET** 응답만 캐시한다(로그인 상태에서). 쓰기 응답은 캐시하지 않는다.
- 🟡 캐시는 토큰(세션) 기준으로 무효화한다. 세션 토큰이 바뀌면 저장하지 않는다(`client.ts` 참고).
- 🟡 세션 만료 시 캐시는 비우되 **오프라인 쓰기 큐는 보존**한다.

## 쓰기 큐 규칙 (가장 위험한 영역)

- 🟡 오프라인 쓰기는 큐에 적재 후 온라인 복귀 시 재전송한다(`SyncService`).
- 🔴 **중복/유실 주의**: 서버 5xx(502/503/504)는 네트워크가 살아있어 쓰기가 이미 반영됐을 수 있다 → GET만 폴백, 쓰기는 폴백하지 않는다.
- ⚠️ 큐 동작(재전송 순서, 멱등성, 충돌 해소) 변경은 **사람 확인 필수**. 데이터 유실/중복 위험.
