# Offline First PR Review Plan

PR #75: `feat: 오프라인 퍼스트 지원 - IndexedDB 캐시 + SyncQueue`

## 이번 PR 수정 계획

### 1. SyncQueue 실패 처리 강화

- `SyncService.ts`에 `MAX_SYNC_RETRY_COUNT` 상수를 추가한다.
- 일시 오류가 반복되는 큐 항목은 재시도 횟수가 한도를 넘으면 `status: 'failed'`로 변경한다.
- `pending` 항목만 flush 대상으로 유지해서 실패 항목 하나가 전체 큐를 영구 차단하지 않게 한다.
- 서버가 명시적으로 거부한 요청의 처리 기준을 정리한다.
  - 기존 영구 실패: `400`, `404`, `409`, `410`, `422`
  - 검토 후 추가 후보: `403`

### 2. 로그아웃 및 계정 탈퇴 시 오프라인 캐시 삭제

- `SyncService.clearAllCache()`를 추가한다.
- `logout()` 성공 후 `clearAccessToken()`과 함께 IndexedDB 캐시를 삭제한다.
- `WithdrawPage.tsx`처럼 `clearAccessToken()`을 직접 호출하는 인증 종료 흐름도 함께 점검한다.
- 삭제 대상은 일지, 복약, 일정, 상담, 리포트, 상세 캐시, 동기화 큐 전체다.

### 3. 복약 로그 캐싱 방어 코드 추가

- `SyncService.cacheMedications()`의 `log.intakeTime.slice(0, 10)` 호출 전에 타입을 확인한다.
- `cacheResponse()`의 `/v1/user-medications/logs` 캐싱 경로에도 같은 방어 로직을 적용한다.
- `intakeTime`이 없거나 문자열이 아니면 해당 로그만 건너뛰고 전체 캐싱은 계속 진행한다.

### 4. 오래된 상세 캐시 정리

- `pruneOldCache()`에서 `scheduleDetails`, `consultationDetails`를 `cachedAt` 기준으로 정리한다.
- 목록 캐시는 날짜 인덱스 기준, 상세 캐시는 저장 시각 기준으로 삭제한다.
- `scheduleDetails` 전체 삭제는 하지 않는다. 사용자가 조회해 둔 상세 캐시는 유지하고 오래된 항목만 제거한다.

### 5. 오프라인 임시 복약 로그 ID 고유화

- 오프라인 quick log 응답에서 `logId: 0` 대신 고유한 음수 임시 ID를 반환한다.
- 같은 밀리초에 여러 개가 생성되어도 중복되지 않도록 `Date.now()`에 카운터 또는 난수를 조합한다.
- 서버 동기화 후 실제 응답으로 대체되는 흐름에는 영향을 주지 않는지 확인한다.

## 검증 계획

- `pnpm build`로 타입 및 번들 검증을 수행한다.
- 수동 확인 항목:
  - 오프라인에서 쓰기 요청이 `syncQueue`에 적재된다.
  - 온라인 복귀 시 pending 큐가 flush된다.
  - 반복 실패 항목은 한도 이후 `failed`로 전환되고 뒤 큐를 막지 않는다.
  - 로그아웃 또는 탈퇴 후 IndexedDB 캐시가 비워진다.
  - `intakeTime` 누락 로그가 있어도 캐싱이 중단되지 않는다.
  - 일정/상담 상세 캐시는 오래된 항목만 정리된다.

## 별도 리팩터링으로 분리

### A. NanumSquare 폰트 스타일 정리

현재 `fontFamily: 'NanumSquare, ...'` 인라인 스타일이 앱 전반에 넓게 퍼져 있다. `OfflineIndicator`만 부분 수정하면 코드 스타일이 더 혼재되므로 별도 리팩터링으로 분리한다.

작업 범위:

- Tailwind 설정에 `font-nanum` 같은 공통 font family 유틸리티를 추가한다.
- 화면 루트나 공통 레이아웃에서 기본 폰트를 선언할 수 있는지 검토한다.
- 반복되는 인라인 `fontFamily`를 공통 클래스 또는 레이아웃 스타일로 치환한다.
- 관리자, 캘린더, 상담, 복약, 리포트, 온보딩 화면까지 한 번에 정리한다.

완료 기준:

- 새 화면에서 폰트 인라인 스타일을 추가하지 않아도 된다.
- 기존 시각 품질이 유지된다.
- 폰트 fallback 순서가 한 곳에서 관리된다.

### B. i18n 기반 도입

현재 앱에는 locale 파일이나 번역 유틸리티가 없다. `OfflineIndicator`의 문구만 locale로 분리하면 구조가 고립되므로, i18n 기반은 별도 작업으로 설계한다.

작업 범위:

- 사용할 i18n 방식 결정: 단순 locale map, `i18next`, 또는 앱 전용 메시지 유틸리티.
- 기본 언어를 `ko`로 두고 문구 키 네이밍 규칙을 정한다.
- 공통 컴포넌트부터 locale 접근 방식을 적용한다.
- 이후 페이지별 하드코딩 문구를 단계적으로 이전한다.

완료 기준:

- 새 UI 문구를 하드코딩하지 않는 기준이 생긴다.
- 번역 키와 fallback 동작이 명확하다.
- 기존 한국어 UX가 깨지지 않는다.

### C. 인증 종료 흐름 통합

이번 PR에서는 필요한 위치에 캐시 삭제를 연결하되, 인증 종료 흐름 자체는 여러 파일에 분산되어 있다. 장기적으로는 로그아웃, 탈퇴, 세션 만료 처리를 하나의 클라이언트 세션 종료 유틸리티로 통합한다.

작업 범위:

- `clearAccessToken()`, guest mode 종료, offline cache 삭제, 기타 로컬 상태 삭제를 하나의 함수로 묶는다.
- API logout 성공/실패와 관계없이 로컬 세션을 정리해야 하는 케이스를 분리한다.
- 401 refresh 실패 경로에서도 동일한 정리 정책을 적용할지 결정한다.

완료 기준:

- 인증 종료 시 로컬 데이터 삭제 누락 가능성이 낮아진다.
- 로그아웃, 탈퇴, 세션 만료 처리 정책이 한 곳에서 보인다.
